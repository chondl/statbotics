# Staging coordination protocol

Multiple agents modify the shared staging environment (branch `staging` on fork, GCP project `statbotics-staging`, bucket `statbotics-staging-site`, Cloud Run services `statbotics-api`/`statbotics-web`). Rules:

1. **Before pushing `fork/staging` or deploying a Cloud Run service:** append a line to the Log below — `[UTC timestamp] <agent-name> INTENT: <push staging | deploy api | deploy web | run update | run backfill>`. Check the log first: if another agent announced an unfinished intent on the same service/branch within the last 30 minutes, wait and poll.
2. **Always** `git fetch fork && rebase/merge fork/staging` immediately before pushing staging. Never force-push `staging`.
3. After your deploy: run the shared smoke suite (docs/superpowers/rig/smoke/), append `[UTC timestamp] <agent-name> DONE: <what> — smoke <result>`, and note it in staging.md.
4. Never redeploy a service to roll back someone else's change; if staging looks broken by another agent's work, note it here and in your final report instead.
5. Long-running operations that change data (historical backfill, full rebuilds) get an INTENT line too — other agents should avoid publishes/deploys that race a running backfill.
